本次导出的分享信息

以下内容根据本次成功导出的文件自动生成。原抓取时间按北京时间 / 香港时间（UTC+8）显示；分享日期默认使用导出当天，稍后发布时请改为实际分享日期。

复制后按下方步骤发帖，并附上本次导出文件的 ZIP。

先点击上方「仅导出收藏数」。导出成功后，这里会自动生成记录数量、原抓取时间范围、客户端版本、分享日期，以及可复制的标题和正文。

  1. 导出并找到收藏数文件

    点击上方「仅导出收藏数」。桌面客户端会弹出保存窗口，选择容易找到的独立文件夹（例如桌面上的分享文件夹），点击保存；浏览器版可按 Ctrl + J 打开下载列表，点击文件旁的文件夹图标或「在文件夹中显示」。找到以 .ehfavorites.json 结尾的文件。取消保存不会生成本次分享信息。

  2. 将文件压缩为 ZIP

    在 Windows 文件资源管理器里，只选中刚导出的收藏数 JSON 文件。Windows 11：右键 →「压缩为」→「ZIP 文件」；若没有该选项，点击「显示更多选项」→「发送到」→「压缩(zipped)文件夹」。Windows 10：右键 →「发送到」→「压缩(zipped)文件夹」。生成的 ZIP 与原文件通常在同一个文件夹。压缩后可双击 ZIP，确认里面只有本次导出的收藏数文件。

  3. 注册或登录 GitHub

    点击上方「打开收藏数分享区」，客户端会使用默认浏览器打开。已登录 GitHub 的用户可直接继续。没有账号时，打开 https://github.com/signup，按页面提示注册并完成邮箱验证；已有账号时，打开 https://github.com/login 登录。登录成功后重新打开分享区。GitHub 账号和源站账号是分别使用的，分享时无需填写源站 Cookie。

  4. 进入正确的分享分类

    收藏数分享区的完整地址：

    https://github.com/IGreyeyes/exhentai-local-catalog/discussions/categories/收藏数分享

    进入后点击「New discussion」（新建讨论）。也可点击上方「新建分享帖」。如果出现分类选择页，请选择「收藏数分享」；进入编辑页后确认 Category（分类）显示「收藏数分享」。

  5. 粘贴自动生成的标题和正文

    在客户端点击「复制标题」，切换到浏览器，点击「Add a title」（添加标题）输入框并按 Ctrl + V。再回来点击「复制正文」，切换到浏览器的「Add a body」（添加正文）编辑框，在「Write」（编辑）标签下粘贴。核对数量、原抓取时间范围和版本，按需修改分享日期，并补充说明。若无法自动复制，选中相应文本后按 Ctrl + C。

  6. 上传 ZIP 附件

    把第 2 步生成的 ZIP 拖进正文编辑框；也可点击编辑框下方「Paste, drop, or click to add files」（粘贴、拖放或点击添加文件），选择 ZIP。等待上传完成，编辑框里出现指向 ZIP 的附件链接后再继续；只有填写标题和正文，不会自动上传文件。附件超过 GitHub 当前大小限制或上传失败时，请按页面提示处理，确认附件上传成功后再发布。

  7. 预览并发布

    点击「Preview」（预览），核对文字、分类和附件链接，然后点击「Start discussion」（发布讨论）。发布成功后会打开帖子页面；确认帖子属于「收藏数分享」并显示 ZIP 附件链接，可以复制浏览器地址栏中的帖子网址给其他用户。之后如需修改，使用帖子正文右上角的「…」菜单 →「Edit」（编辑）。

  8. 其他用户如何下载和合并

    打开分享帖，点击 ZIP 附件链接下载。下载后右键 ZIP →「全部提取」，取得 .ehfavorites.json 文件。打开客户端的「资料库维护 → 收藏数导入导出」，在下方选择解压后的 JSON，点击「检查收藏数文件」，核对预计新增、更新和保留数量，勾选确认，再点击「备份当前资料并合并收藏数」。合并按下方规则处理，不会把原抓取时间改成分享或导入时间。

分享前确认公开范围

收藏数导出包含本地全部成功记录（含他人数据及成功取得的零收藏），以及作品 ID、收藏数、原抓取时间、源站、原采集者 ID 和昵称。这些信息和你的 GitHub 发帖账号会公开，请核对后自行决定是否分享。

只上传收藏数导出文件的 ZIP。完整资料库、备份、.ehcollector.json 身份迁移文件、.ehcred 登录文件、Cookie、密码和日志请自行保管。

收藏数如何合并

先按作品 ID（GID）匹配。同一个作品只保留一条收藏数记录。

自己的 / 他人的数据：用导入记录的原采集者 ID，与上方「我的 ID」比较。昵称相同不代表同一个采集者。

导入记录的情况程序如何处理
本地还没有成功收藏数直接新增，收藏数为 0 也可新增；保留原抓取时间、源站和采集者。
自己的数据
采集者 ID 与我的 ID 相同		须同时满足：抓取时间更晚，而且收藏数更大，才覆盖；任一条件不满足就保留本地记录。
他人的数据
采集者 ID 非空且与我的 ID 不同		只要收藏数更大就覆盖，不比较抓取时间；时间相同或更旧也可以。
采集者未知的旧数据沿用原规则：抓取时间更晚，而且收藏数更大，才覆盖。

已有记录的收藏数相同或减少时，一律保留本地记录。接受覆盖时，收藏数、原抓取时间、源站和原采集者一起替换；不会改成导入时间，也不会归到导入者名下。

例如：本地收藏数为 100，导入的是更早抓取的 120。来自他人时会更新为 120；来自自己或未知采集者时会保留 100。即使本地原记录也是这位他人采集的，仍以「我的 ID」判断。

检查文件只显示预计结果。确认合并后，程序暂停采集并自动备份，再按当时的数据执行上述规则。重复导入同一文件不会新增重复作品；阅读状态、黑名单和采集队列保留。
